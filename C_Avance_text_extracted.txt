1. Présentation du projet
Le projet consiste à développer un logiciel de traitement de texte intelligent, baptisé IntelliEdit or, développé
en langage C, destiné à fonctionner entièrement hors ligne sur Windows. Il combine les fonctionnalités
classiques d'un éditeur de texte avec des capacités d'intelligence artificielle intégrées directement dans
l'application, sans recours à un serveur distant ou à une connexion Internet.
Le logiciel est conçu pour accompagner les étudiants finalistes et chercheurs dans la rédaction de documents
structurés (mémoires, rapports, articles), en leur offrant une assistance active à chaque étape : correction
linguistique, reformulation stylistique, et respect automatisé de règles de rédaction définies à l'avance.

3.1 Principes architecturaux
Séparation des r esponsabilit és : chaque module expose une API C claire ; les modules ne s'appellent
pas directement en dehors de cette API.
Asynchr onisme  : toutes les requêtes LLM (lentes) s'exécutent dans un thread séparé. L'UI n'est jamais
bloquée.
UTF-8 int erne : tout le pipeline interne utilise UTF-8. La conversion vers UTF-16 (WinAPI) se fait
uniquement aux points d'entrée/sortie système.
Tolérance aux p annes  : si le LLM est indisponible ou trop lent, les fonctionnalités de base (édition,
Hunspell) restent pleinement opérationnelles.

Pour la grammaire et la reformulation, une requête est envoyée au LLM avec un prompt structuré. La réponse

4.4 Moteur LLM embarqué
Le LLM est intégré via llama.cpp , dont l'API C est stable et maintenue activement. L'inférence tourne
entièrement sur CPU.
Gestion des per formances :
Le modèle est chargé une seule fois au démarrage (5–15 secondes selon le modèle)
Un indicateur de chargement est affiché dans la barre de statut
Les requêtes sont mise en file et traitées séquentiellement
Un timeout de 30 secondes par requête est appliqué
Le contexte K V est réutilisé entre requêtes similaires

9.3 Critères d'évaluation
L'évaluation est individuelle , même si le projet est collectif.
Critère Poids
Structure du code et qualité du logiciel ~30 %
Exposé individuel oral ~70 %
L'exposé oral est le critère princip al. Chaque étudiant devra expliquer clairement, devant l'enseignant,
le code qu'il a écrit : les choix techniques effectués, le fonctionnement des algorithmes et structures de
données utilisés, et les difficultés surmontées. Un étudiant incapable d'expliquer son propre code
obtiendra une note très faible, indépendamment de la qualité du logiciel livré.
L'exposé sera organisé à la fin du cours. La date exacte sera communiquée ultérieurement.
